## What Do These Words Actually Mean?

| Term | Meaning | Example |
|---|---|---|
| **Game tree** | Every possible sequence of future moves, represented as branches | Each Siege Table move creates new branches for every possible response |
| **Adversarial search** | Searching a game tree assuming the opponent always plays their best possible move against you | Minimax |
| **Maximizing player** | The player trying to get the highest possible score | The recruit, played by the human |
| **Minimizing player** | The player trying to get the lowest possible score | The Strategist |
| **Terminal state** | A finished game — win, loss, or draw — where no more moves are possible | A full Siege Table, or three banners in a row |
| **Minimax** | The algorithm that picks a move by assuming both players play perfectly | Explored fully in Checkpoints 1–2 |
| **Alpha-beta pruning** | An optimization that skips branches of the game tree that can't possibly change the outcome | Checkpoint 3 |
| **Tensor** | PyTorch's core data structure — like a NumPy array, but able to track gradients for training | `torch.tensor([1, 2, 3])` |
| **Forward pass** | Running input data through a neural network to get an output | `model(input_data)` |
| **Loss function** | A number measuring how wrong a model's prediction was | `CrossEntropyLoss` |
| **Training loop** | The repeated process of: predict, measure loss, adjust weights, repeat | Checkpoint 4 |
| **Rule-based AI** | Decisions made by explicit, human-written logic | Minimax, `if`/`elif` thresholds |
| **Learned AI** | Decisions made by a model that inferred patterns from example data | A trained neural network |

| Term | What it means |

### 🧠 Understand It First

**Block 1 — Representing the board and checking for a winner:**

A Siege Table board is just a list of 9 cells — `"X"` for Crown, `"O"` for Shadow, or `None` for an empty position. As you read `check_winner`, find all 8 ways to win (3 rows, 3 columns, 2 diagonals) and confirm the function actually checks every one of them.

```python
# sandbox_minimax_basics.py  — Block 1

def check_winner(board):
    win_lines = [
        (0, 1, 2), (3, 4, 5), (6, 7, 8),   # rows
        (0, 3, 6), (1, 4, 7), (2, 5, 8),   # columns
        (0, 4, 8), (2, 4, 6),               # diagonals
    ]
    for a, b, c in win_lines:
        if board[a] is not None and board[a] == board[b] == board[c]:
            return board[a]   # "X" (Crown) or "O" (Shadow)
    return None   # no winner (yet)

def get_available_moves(board):
    return [i for i, cell in enumerate(board) if cell is None]

def is_full(board):
    return all(cell is not None for cell in board)

# Crown has won along the top row
test_board = ["X", "X", "X",
              "O", "O", None,
              None, None, None]

print(check_winner(test_board))           # "X"
print(get_available_moves(test_board))     # [5, 6, 7, 8]
print(is_full(test_board))                  # False
```

**Block 2 — Scoring a finished game, and the idea of maximizing vs. minimizing:**

Before any recursion, you need to know what a GOOD outcome even looks like from each side's perspective. As you read this, notice that the SAME final board produces a score of `+1` from one side's point of view and `-1` from the other's — that opposite relationship is the entire foundation of minimax.

```python
# sandbox_minimax_basics.py  — Block 2

def evaluate(board):
    """
    Scores a FINISHED board from Crown's perspective:
      +1 if Crown ("X") won, -1 if Shadow ("O") won, 0 if it's a draw.
    Crown is always treated as the MAXIMIZING player — trying to get the
    score as HIGH as possible. Shadow (the Strategist) is the MINIMIZING
    player — trying to get it as LOW as possible.
    """
    winner = check_winner(board)
    if winner == "X":
        return 1
    elif winner == "O":
        return -1
    else:
        return 0   # draw, or not finished (we'll only call this on finished boards for now)

crown_wins  = ["X", "X", "X", "O", "O", None, None, None, None]
shadow_wins = ["O", "O", "O", "X", "X", None, None, None, None]
draw        = ["X", "O", "X", "X", "O", "O", "O", "X", "X"]

print(evaluate(crown_wins))    # 1  — good for the maximizing player
print(evaluate(shadow_wins))   # -1 — good for the minimizing player
print(evaluate(draw))            # 0  — neither side gained an advantage
```

**Block 3 — A tiny traced minimax, on an almost-finished board:**

Full games explored from an empty board take a long time to trace by hand, so this example starts from a board with only ONE empty cell left — small enough to read every recursive call. As you run it, follow the indentation and find exactly where the recursion bottoms out.

```python
# sandbox_minimax_basics.py  — Block 3

def minimax_traced(board, is_maximizing, depth=0):
    indent = "  " * depth
    winner = check_winner(board)
    if winner is not None or is_full(board):
        score = evaluate(board)
        print(f"{indent}Terminal state, score = {score}")
        return score

    if is_maximizing:
        best_score = float("-inf")
        for move in get_available_moves(board):
            board[move] = "X"
            print(f"{indent}Crown tries move {move}")
            score = minimax_traced(board, False, depth + 1)
            board[move] = None   # undo the move — this board is REUSED for every branch
            best_score = max(best_score, score)
        print(f"{indent}Best score for Crown here: {best_score}")
        return best_score
    else:
        best_score = float("inf")
        for move in get_available_moves(board):
            board[move] = "O"
            print(f"{indent}Shadow tries move {move}")
            score = minimax_traced(board, True, depth + 1)
            board[move] = None
            best_score = min(best_score, score)
        print(f"{indent}Best score for Shadow here: {best_score}")
        return best_score

# Only ONE empty cell left — small enough to trace by hand
almost_done = ["X", "O", "X",
               "X", "O", "O",
               "O", "X", None]
minimax_traced(almost_done, True)   # it's Crown's (maximizing player's) turn
```

Notice `board[move] = None` right after the recursive call — the SAME board is reused for every branch, so each move has to be undone before trying the next one. This should look familiar: it's the exact same "try it, then undo it" pattern as the maze backtracking from Unit 3.

### 💡 Hints

**The overall shape every minimax function follows — this shape doesn't change all unit:**

```python
def minimax(board, is_maximizing):
    # Step A: Check for a terminal state FIRST — always
    winner = check_winner(board)
    if winner is not None or is_full(board):
        return evaluate(board)

    # Step B: If maximizing, try every move, keep the HIGHEST resulting score
    # Step C: If minimizing, try every move, keep the LOWEST resulting score
    # Step D: Whichever branch you're in, always UNDO the move before trying the next one
```

**Why the terminal-state check has to come first, not last:**

If you tried to call `get_available_moves(board)` on a board that's already full, you'd get an empty list — and looping over an empty list with `max()`/`min()` would crash, since there's nothing to compare. Checking "is this over?" before anything else avoids that entirely.

**A common mistake — forgetting to undo a move:**

```python
# WRONG — never undoes board[move], so every future branch sees ALL previous
# test moves still sitting on the board, which corrupts every result after the first
for move in get_available_moves(board):
    board[move] = "X"
    score = minimax(board, False)
    best_score = max(best_score, score)
    # MISSING: board[move] = None
```

### 🧠 Understand It First

Create `sandbox_best_move.py`.

**Block 1 — From "score a position" to "pick the best move":**

`minimax` alone only tells you a number — it doesn't tell you WHICH move produced that number. `find_best_move` below tries every available move, asks minimax to score what happens next, and remembers whichever move led to the best outcome. As you read it, notice it's really just ONE layer of the maximizing loop from `minimax` itself, pulled out on its own.

```python
# sandbox_best_move.py  — Block 1
from siege_table import check_winner, get_available_moves, is_full, evaluate, minimax

def find_best_move(board, symbol):
    is_maximizing = (symbol == "X")
    best_score = float("-inf") if is_maximizing else float("inf")
    best_move = None

    for move in get_available_moves(board):
        board[move] = symbol
        score = minimax(board, not is_maximizing)
        board[move] = None   # undo — same pattern as always

        if is_maximizing and score > best_score:
            best_score = score
            best_move = move
        elif not is_maximizing and score < best_score:
            best_score = score
            best_move = move

    return best_move

# Crown to move, with a way to win — minimax should find it
board = ["X", "X", None,
         "O", "O", None,
         None, None, None]
print(f"Best move for Crown: {find_best_move(board, 'X')}")   # should be 2 (completes the row)
```

## Checkpoint 3 — Alpha-Beta Pruning ✂️

### 📋 Your Task

Checkpoint 2 proved the Strategist works, but the empty-board node count you measured is enormous for a game as small as Siege Table — and would be completely unworkable for a bigger game. Alpha-beta pruning fixes this by skipping branches that can't possibly change the final answer, **without changing what move gets picked**. You'll upgrade the Strategist to use it, and — since he's an `NPC` making a decision — hook `@log_action` from Unit 2 onto his move so every match gets logged automatically.

### 🧠 Understand It First

Create `sandbox_alphabeta.py`.

**Block 1 — Seeing a prunable branch by hand, with tiny made-up numbers:**

Forget Siege Table for a moment — this tree is just numbers, small enough to reason about directly. As you read it, work out: once the maximizing player has already found a branch worth `5`, is there ANY way the second branch (starting with a `2`) could end up being chosen over it, once the minimizing player is guaranteed at least one option worth `2` or less inside it?

```python
# sandbox_alphabeta.py  — Block 1

# Imagine this tiny game tree (not a real Siege Table game, just abstract numbers):
#
#              MAX
#            /      \
#         MIN        MIN
#        /   \       /   \
#       3     5     2     ?
#
# The left MIN node will choose min(3, 5) = 3.
# The right MIN node starts by looking at its FIRST child: 2.
# Since MIN wants the SMALLEST score, the right branch can NEVER score higher
# than 2, no matter what "?" turns out to be — 2 is already an upper limit for it.
#
# The MAX node, meanwhile, already has a guaranteed option worth 3 (from the left).
# Since the right branch can score AT MOST 2, and MAX already has a 3 available,
# there is NO POSSIBLE VALUE for "?" that would make MAX prefer the right branch.
#
# Alpha-beta pruning means: the moment we see that first "2," we can SKIP
# checking "?" entirely — it cannot change the outcome. This is called pruning
# the branch.

print("Left branch: MIN chooses min(3, 5) = 3")
print("Right branch: MIN's first option is already 2, worse than the left's 3")
print("MAX will pick the left branch no matter what '?' is — the right branch is PRUNED")
```

**Block 2 — Alpha-beta minimax, with `alpha` and `beta` tracking the bounds:**

`alpha` is the best score MAX can already guarantee somewhere else in the tree; `beta` is the best score MIN can already guarantee. As you read the pruning check (`if beta <= alpha`), connect it back to Block 1's reasoning — that condition is exactly "the opponent already has a better option than anything left in this branch could offer."

```python
# sandbox_alphabeta.py  — Block 2
from siege_table import check_winner, get_available_moves, is_full, evaluate

def minimax_ab(board, is_maximizing, alpha, beta):
    winner = check_winner(board)
    if winner is not None or is_full(board):
        return evaluate(board)

    if is_maximizing:
        best_score = float("-inf")
        for move in get_available_moves(board):
            board[move] = "X"
            score = minimax_ab(board, False, alpha, beta)
            board[move] = None
            best_score = max(best_score, score)
            alpha = max(alpha, best_score)
            if beta <= alpha:
                break   # PRUNE — the minimizing side already has something better elsewhere
        return best_score
    else:
        best_score = float("inf")
        for move in get_available_moves(board):
            board[move] = "O"
            score = minimax_ab(board, True, alpha, beta)
            board[move] = None
            best_score = min(best_score, score)
            beta = min(beta, best_score)
            if beta <= alpha:
                break   # PRUNE — the maximizing side already has something better elsewhere
        return best_score

# Called with alpha starting as -infinity, beta starting as +infinity —
# neither side has ANY guarantee yet at the very top of the tree
almost_done = ["X", "O", "X", "X", "O", "O", "O", "X", None]
```
